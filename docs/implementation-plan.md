# Kiro ACP Bridge Implementation Plan

**Goal:** Complete the scaffold as a small OpenCode provider backed exclusively by official `kiro-cli acp`, with tools executed by OpenCode.

**Architecture:** Select verified ACP **v2** explicitly (`--agent-engine v2`), one child process per active `(sessionID, agent)` scope, and a token-authenticated loopback MCP endpoint bound directly to that scope. Translate OpenAI-compatible chat requests into ACP turns; park MCP calls while OpenCode executes the corresponding tools. Kiro owns authentication and its native session storage.

**Tech stack:** Existing strict TypeScript/NodeNext, Node >=22.13, Node child-process/HTTP/crypto APIs, installed `@opencode-ai/plugin` types, Bun offline tests. No ACP/MCP framework or new runtime dependency is required initially.

**Status (2026-10-22):** Momus approved the original plan (OKAY). Shared type-only contracts are frozen in `src/contracts.ts`; recovered R1/R2/R3 evidence is reconciled here without redesign. Runtime implementation remains assigned to disjoint workers; main is orchestration only. The requested general → OpenAI Sol 6.1 mapping is assumed configured and must not be changed. This reconciliation performs no real Kiro calls, credential access, agent/provider configuration edits, dependency additions, or git mutations.

**Current local status (2026-10-23):** Implementation and native two-prompt continuation/schema-reload acceptance are complete. That native proof predates the final cancellation-only fix; current-tree offline and nine-check packed real-host QA cover the corrected parked-tool abort/recovery gate. See [integration QA](integration-qa.md) and [parked abort](parked-abort.md). Final independent delta review completed: **APPROVE, no blocking findings**; the package remains unpublished. ## 3. Runtime decisions

### Scope, routing and permissions

1. Obtain session/agent from `chat.headers` for provider `kiro`; use explicit headers (`x-opencode-session`, URI-encoded `x-opencode-agent`). Scope lookup also includes the plugin instance/project boundary. Reject missing, malformed or mismatched scope; never fall back to a global conversation.
2. Lazily create a private scratch directory per scope (directory mode 0700, files 0600), a random endpoint bearer token, and `.kiro/agents/opencode.json`. Spawn via `execFile`/`spawn`, never a shell, using `KIRO_CLI || "kiro-cli"`, arguments `acp --agent-engine v2 --agent opencode --model <validated-id>`, and that scratch cwd. C constructs this exact argument vector; A passes it unchanged. Use the same scratch cwd in ACP new/load. No engine fallback.
3. Agent configuration: `name: "opencode"`, a short prompt to follow the instruction resource, `resources: ["file://./AGENTS.md"]`, `tools: ["@opencode"]`, `includeMcpJson: false`, validated model, and `mcpServers.opencode` with the scope's loopback URL, private authentication header, and `timeout: 7200000`. Verify the precise agent HTTP `headers` field shape once (gate G1 below), rather than guessing it. Do not register the server again through ACP session parameters.
4. One HTTP listener may serve all scopes on `127.0.0.1` with distinct opaque paths/tokens. Bind port 0; verify host/origin, authentication and content type before MCP dispatch. Treat `Mcp-Session-Id` as transport state within an already authenticated scope, never as scope identity. Reject cross-scope IDs and unknown methods; bound request/line/argument sizes (initially 8MiB), not tool duration to 120s. Do not log tokens, headers, prompts or full CLI stdout/stderr.
5. Implement the small MCP subset actually used: initialize/initialized, tools/list, tools/call, cancellation/DELETE cleanup, and `notifications/tools/list_changed` when supported. Expose only the current OpenCode request's tools. Return original parameter schemas, stable reversible tool names and descriptions; strip only verified Kiro transport additions such as `__tool_use_purpose` before emitting OpenCode arguments. Validate calls against the current schema with the existing OpenCode execution boundary; reject unknown/stale tools locally. No local tool execution in this server.
6. ACP client advertises filesystem read/write and terminal capabilities **false**. Respond to arbitrary fs/terminal requests with protocol errors. At each permission request A reads `getApprovedTools()` and requires an exact verified `(serverName, toolName)` MCP identity from the request; only a matching one-use permission may be selected. Missing/ambiguous identity, no matching current tool, or no one-use option means deny. C supplies `() => endpoint.approvedTools`; B publishes the current wire identities after name mapping and clears them on close. Never copy the probe's blanket permission-allow implementation. Disable discovery of unrelated MCP servers/resources; inherited user custom agents must not broaden permissions.

### Chat/tool loop and identity

- Serialize requests within a scope; allow different scopes concurrently. Assign each turn a generation. Record normalized **non-system** messages (exclude both system and developer instruction roles), model and unresolved tool IDs. A request may resume only when its non-system history matches the committed prefix and its tool-result suffix matches held IDs. Instruction text never participates in session identity/prefix hashing.
- Divergence, compaction, missing history or model change: cancel/release old gates and start a clean ACP session with normalized history, avoiding duplicate submission of prior turns. Idle process eviction may retain the ACP session ID in memory for same-scope `session/load`; replay notifications during load are reconciliation, not fresh output. Do not infer continuity from prompt text similarity. No transcript database or durable cross-restart scope registry initially.
- Before **every** prompt/continuation, atomically rewrite the scratch `AGENTS.md` with the current request's system/developer instructions and actual project directory. Resource rereading on a new prompt is proven; rereading during a parked MCP continuation is not. If instructions change while parked, cancel/release and rebuild with the supplied tool results under a new prompt, rather than resuming with stale instructions. Kiro's cwd stays isolated; OpenCode tools retain OpenCode's real workspace context. Never copy arbitrary workspace files or credentials into scratch.
- Each MCP `tools/call` creates a held gate and emits one OpenAI tool call with a stable OpenAI call ID. Finish that HTTP chat response with `finish_reason: "tool_calls"` while the ACP prompt and MCP request remain parked. Next OpenCode request supplies tool results; verify IDs/generation, resolve gates exactly once, then stream ACP continuation into the new response. Returning tool-call SSE is **not** an abort of the parked turn.
- Keep tools/list backed by the latest request definitions. Before a new prompt, notify list changes if supported. If v2 caches schemas, respawn/load at a quiescent boundary to force initialize/tools/list; prove load reattachment at G1. Never change a held tool's definition. If a held turn encounters incompatible tool definitions or cannot safely reattach, cancel and rebuild from OpenCode history rather than guessing a cached definition.
- Parallel held calls must map by IDs, never arrival order. Cancellation applies to the whole ACP turn and releases every gate in it. Start with tests for two concurrent gates; no extra batch scheduler.

### Abort, HTTP and process lifecycle

- Propagate `init.signal` or the input Request's signal. An actual abort/client stream cancellation sends `session/cancel`, rejects/resolves held MCP requests as cancelled, clears timers/listeners and prevents late output. Keep a successfully closed tool-call response distinct from a cancelled stream.
- After cancellation, wait for trailing turn metadata with a bounded deadline (2s initially); if not quiescent, respawn before another prompt. Do not blindly retry a paid prompt. For a tool exceeding the configured two-hour bound, cancel/release and return a timeout; retain completed OpenCode results for explicit continuation rather than a fabricated result.
- ACP client drains stdout and stderr, parses newline JSON incrementally, correlates JSON-RPC IDs and session notifications, preserves useful sanitized `error.data`, and rejects pending calls on EOF/malformed protocol/exit. Use bounded control-request timeouts; prompt/held-tool timeout must permit the configured long-call window.
- Lazy processes; ten-minute quiescent idle eviction initially, never evict a legitimate held tool as merely idle. OpenCode idle/abort/deleted events must distinguish a running tool from abandoned work. `dispose` closes all gates, responses, listener, timers and child/launcher descendants owned by this plugin. Graceful shutdown then forced termination after 2s; no broad `pkill`. Delete only plugin scratch files. Native Kiro session files/logs belong to Kiro: do not read credentials, bulk-delete sessions, log out, or modify shell/global settings.

### Models, output and authentication

- Reuse `currentModels()` before launch. Reject an ID absent from its catalog; if only fallback `auto` is available, permit only `auto` with an explicit unavailable-catalog message for other selections. A stale cached catalog can still fail upstream: surface that error without repeatedly retrying it. Exact forced-refresh UX is deferred; do not add a second catalog implementation.
- Provide OpenAI chat SSE (role/text/tool-call deltas, finish reason, `[DONE]`) and matching non-stream responses. Return structured `{ error: { message, type, code } }` HTTP errors before headers; after SSE starts emit an error event and terminate without a success finish. Invalid request/model 400, missing login 401, verified rate-limit classification 429, upstream/protocol failure 502, deadline 504. Preserve AbortError semantics. R3's issue-derived quota/auth strings are tentative classifiers, not proven ACP fixtures.
- Do not expose effort variants unless actual CLI/model capability evidence supports them. Do not map metadata `reasoning` capability information to thought text. Omit native token usage when absent; if OpenCode requires numeric accounting, expose a clearly labelled estimate separately and document its calculation/limitations. Context percentage and credit consumption are not tokens or dollar prices. Provider context comes from the catalog; any output-limit reserve is explicitly a local accounting reserve, not a vendor maximum.
- Image deferral lifted by the user (2026-10-28): advertise image attachments provider-wide, gate them on `agentCapabilities.promptCapabilities.image === true`, and accept bounded PNG/JPEG/GIF/WebP base64 data attachments. Never fetch external image URLs or infer per-model vision. Current bridge support is offline-verified through real OpenCode + fake Kiro; native v2 image model verification remains a separate authorized step. Historical pixels are omitted on reconstruction. See [image input](image-input.md). Thinking/effort variants remain deferred.
- Authentication stays in `kiro-cli login`. Add one auth method labelled CLI login, with instructions/prompt to run it in a terminal (optional device-flow instructions for SSH); no pasted key, browser-URL scraping or undocumented login-output parsing. Installed `AuthHook` supports an API-shaped method with text prompts and custom `authorize`; use that merely as the OpenCode credential-registration UI, returning a non-secret `kiro-cli-managed` sentinel after successful checks.
- Check executable/version and `whoami -f json` (10s command timeout); parse only its first JSON line and retain only authenticated/not-authenticated status. On user-initiated login completion, poll at 2s intervals for at most 60s. Missing CLI, timeout, logged-out or unsupported identity fails clearly with terminal instructions; never run login/logout automatically or touch existing login. Unknown future identity output fails explicitly, rather than assuming it is logged out. Successful request-side checks may cache for 60s; invalidate after upstream auth failure.
- Login wins over `KIRO_API_KEY`; bogus-key-with-login does not validate standalone API-key ACP auth. Do not offer API-key auth until separately proven. Never run `kiro-cli doctor`, even as diagnostics. Preserve the user's HOME/auth environment; isolated tests use fakes and isolated HOME, not copied credential stores.

## 4. Small typed boundaries and disjoint ownership

**`src/contracts.ts` is the canonical frozen type-only contract.** Retain the approved section 4 shapes with readonly data and the necessary current-permission-identity seam. No runtime logic, dependencies, engine adapter, or additional auth abstraction belongs there. Wire input remains `unknown` until validated; ACP wire method types stay local to `acp.ts`. Use installed `Plugin`/`Hooks` types directly in the plugin.

```ts
// Implement/export these functions from their owning modules, not contracts.ts:
createAcpClient(options: AcpClientOptions): AcpClient
createToolServer(): Promise<ToolServer>
createBridge(options: BridgeOptions): Promise<Bridge>
```

`AcpClientOptions` is `{ executable: string; args: readonly string[]; cwd: string; onEvent: (event: AcpEvent) => void; getApprovedTools: () => readonly ApprovedMcpTool[] }`; `ApprovedMcpTool` is `{ serverName: "opencode"; toolName: string }`. `BridgeOptions` is `{ executable: string }`. `ToolServer.endpoint(scope: Scope, onCall: (call: ToolCall) => void): ToolEndpoint` and `close(): Promise<void>` retain the approved server API. `ToolEndpoint.approvedTools` is a live readonly snapshot from the latest `setTools`, using exact MCP wire names rather than titles/ACP IDs; C passes its getter to A. All data properties are readonly; prompt content is `readonly PromptBlock[]`. The remaining client/endpoint/bridge methods are exactly those in `src/contracts.ts`. Tool endpoint owns MCP request ↔ OpenAI call-ID mapping; bridge owns turn/session state. ACP `tool` events are advisory and must not emit duplicate calls already emitted by MCP. Auth subprocess checking stays plugin-local.

`ToolEndpoint.waitReady(signal: AbortSignal, timeoutMs?: number): Promise<void>` acknowledges authenticated initialize → initialized → current `tools/list` response on one live endpoint-local session. The deadline defaults to and is capped at 15 seconds. `setTools` invalidates previous readiness; release/close reject pending waiters, and abort rejects only its waiter. Bridge awaits this after every new/load open before prompting, including endpoint/schema replacement. ACP signatures remain unchanged.
